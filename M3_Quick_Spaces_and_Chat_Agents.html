Quick Spaces 與 Chat Agents

用 Spaces 彙整知識、打造客製 Chat Agent,並寫出有效的 BI 提示詞。
學習目標： 說明 knowledge bases/connectors 如何擴充代理能力 · 建立 Space 並加入知識資源 · 設定客製 chat agent · 撰寫有效 BI 提示詞

重點概念

Key Concepts · 知識庫/連接器 → Spaces → Chat Agents → 提示工程
🗂️
01

Knowledge Bases vs Connectors

Knowledge Bases vs Connectors

Knowledge bases 索引內容供代理檢索(唯讀);Connectors 讓代理在外部系統執行動作(讀寫)。

🔗
02

六種資料存取整合

Data Access Integrations

Amazon S3、Web Crawler,以及 OneDrive、SharePoint、Google Drive、Confluence 四種第三方工具。

🧰
03

六大類 Connector

Connector Categories

AWS 服務、專案管理(Asana/Jira)、CRM/客服(Salesforce/Zendesk)、生產力(Slack/Teams)、開發工具、IT/維運;亦支援自訂 REST API 與 MCP server。

📦
04

Quick Spaces 三種型態

Three Space Types

Personal(個人)、Team(部門共用)、Cross-functional(跨部門協作),差異只在內容範圍與分享對象。

📥
05

加入 Space 的五種知識

Adding Knowledge

檔案上傳、Knowledge bases、Actions、Dashboards、Datasets,皆遵循原始存取權限(上傳檔案除外,對空間成員全開放)。

✅
06

管理 Space 最佳實務

Space Best Practices

用領域/專案命名、寫清楚用途說明、定期清除過時內容、留意連結資源(儀表板刪除後空間內會靜默失效)。

🤖
07

系統代理 vs 客製代理

System vs Custom Agent

系統聊天代理預設可用、依使用者權限動態存取資源;客製代理可指定 persona、知識來源與 connector,分享後才對他人可見。

🏗️
08

建立客製代理的三種方式

Three Ways to Build

從範本開始、用自然語言描述(格式:做什麼/給誰/主題/能力/語氣)、或在 Builder view 手動設定 persona、參考文件與資源。

✍️
09

提示詞六大元件

Prompt Components

Task、Instruction、Input、Output、Tone and style、Constraints,組合起來能大幅提升 BI 回答的相關性與可用性。

🧪
10

Lab 2

Lab 2

用 Quick Spaces 建立知識庫,再設定一個能依此空間內容回答問題的客製 HR chat agent。

⭐

一句話總結

提示詞公式:Input(去哪找)+ Task(做什麼)+ Output(什麼格式),是每次問 BI 問題最少要給的三件事。
